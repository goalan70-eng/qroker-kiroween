# Kiro Crew 작업 명세: QRoker 광학 모듈 (Phase 2)

이 문서는 Kiro Crew가 광학 모듈을 구현할 때 따르는 실행 명세다. 설계와 요구사항을 다시 정하지 않고, 승인된 문서를 구현하고 검증한다.

## 1. 목적과 범위

- **목적**: 52장 카드를 이미지로 식별하고 4장의 합산을 정확히 계산하는 독립 광학 모듈을 `src/optical/`에 구현하고, 모든 단계를 자동화 테스트로 검증한다.
- **범위 안**: 코드북 생성·동결, 8변환 검증, 무늬별 조각 생성, 이미지 판독, 4장 식별과 합산, 거부 규칙, 합성 이미지 강건성 측정, 실물 촬영 시험 준비 문서.
- **범위 밖 (구현 금지)**: 게임 엔진, 보드, 덱, 드로우, AI, 시뮬레이터, 점수 수치, 브라우저 UI, PWA, Scoring Companion 앱. 해당 폴더도 만들지 않는다.

## 2. 입력 문서 (읽기 전용)

작업 시작 시 아래를 읽고 이후 변경하지 않는다.

| 파일 | 용도 |
|---|---|
| `.kiro/specs/qroker-game/tasks.md` | 실행할 작업 목록. 체크박스 상태만 갱신할 수 있다 |
| `.kiro/specs/qroker-game/design.md` | 광학 설계의 기준. 특히 "Optical Marker System" 1~8절과 Property 12~15, 20~26 |
| `.kiro/specs/qroker-game/requirements.md` | Requirement 5, 12, 13, 14 |
| `docs/open-decisions.md` | 이 작업을 막지 않는 미결정 사항 |

문서 간 모순이나 설계 오류를 발견하면 문서를 고치지 않는다. `docs/optical/results/findings.md`에 근거와 함께 기록하고 해당 지점에서 멈춘 뒤 사람의 검토를 기다린다.

## 3. 실행 방식

- Task Runner **1개**가 `tasks.md`의 작업을 **순서대로** 실행한다. 병렬 에이전트나 병렬 작업은 쓰지 않는다.
- 마일스톤 간 의존성은 직렬이다. 앞 마일스톤의 테스트 결과가 기록되기 전에 다음 마일스톤을 시작하지 않는다.
- **시작은 코드북 생성기다.** 마일스톤 0(스캐폴딩)을 마친 뒤 곧바로 마일스톤 1을 진행한다.
- 권장 검토 지점: **마일스톤 2 완료 후**와 **마일스톤 6 완료 후**. 코드북은 인쇄하면 바꿀 수 없는 유일한 산출물이므로 2 이후 사람이 확인한다. 이 지점에서 Task Runner는 중간 보고를 남긴다.

## 4. 브랜치와 변경 규칙

- 모든 변경은 Crew 작업 브랜치에서만 한다. 작업 브랜치 이름은 Crew가 지정한 것을 따른다.
- 자동 병합, 자동 push, 패키지 게시(`npm publish`)를 하지 않는다. 커밋은 작업 브랜치에서만 한다. 병합은 사람이 검토한 뒤 수행한다.
- `main`을 직접 수정하지 않는다. 강제 push, 히스토리 재작성, 브랜치 삭제를 하지 않는다.
- 변경 허용 위치: `src/optical/`, `scripts/`, `docs/optical/`, 루트의 `package.json`, `tsconfig.json`, Vitest 설정, `.gitignore`. 그 밖의 파일은 수정하지 않는다.
- 의존성은 `typescript`, `vitest`, `fast-check`와 스크립트 실행기(필요할 때만)로 제한한다. 런타임 의존성은 추가하지 않는다.

## 5. 마일스톤 실행 루프

각 마일스톤에서 다음을 순서대로 수행한다.

1. `tasks.md`의 해당 하위 작업을 구현한다.
2. 테스트를 작성한다. 설계의 Property 번호를 테스트 이름이나 주석에 남긴다.
3. `npm test`를 실행한다. 마일스톤에 전용 스크립트가 있으면 함께 실행한다.
4. **실제 출력**을 `docs/optical/results/`에 저장한다(`mN-*.txt`, 필요 시 `.json`, 짧은 `.md` 보고).
5. 실패가 있으면 아래 6절에 따라 기록한다. 통과를 확인하기 전에는 체크박스를 완료로 바꾸지 않는다.
6. 모두 통과했을 때만 커밋하고 다음 마일스톤으로 넘어간다. 커밋 메시지는 마일스톤 번호를 포함한다.

## 6. 실패 처리와 기록

- 실패한 테스트, 오류 메시지, 실패 시드, 조건을 결과 파일에 **있는 그대로** 기록한다.
- 임계값, 허용 오차, 기대 수치를 완화해서 실패를 통과로 바꾸지 않는다.
- 구현 결함이면 고친 뒤 재실행하고, 실패와 수정 내용을 둘 다 기록한다.
- 설계 결함이나 기준 수치 불일치이면 고치지 않고 `findings.md`에 기록한 뒤 멈춘다.
- 마일스톤 7에서 오식별 건수가 0이 아니면 해당 마일스톤을 "실패, 조사 필요"로 표시하고 실패 시드와 조건을 남긴다.

## 7. 금지 사항

- 테스트를 실행하지 않고 통과했다고 쓰지 않는다.
- 합성 이미지 결과를 실물 카메라 결과처럼 쓰지 않는다. 모든 강건성 보고서에는 "synthetic images, not real cameras"를 명시한다.
- 판독 실패를 기대값이나 보드 상태로 대체하지 않는다. 판독기 함수는 보드 상태 매개변수를 갖지 않는다.
- 반사 여부를 판별할 수 없을 때 어느 쪽으로도 추측하지 않고 `AMBIGUOUS`로 보고한다.
- 코드북 검증기는 생성기나 생성기가 쓰는 변환 구현을 import하지 않는다. 검증 로직은 자체적으로 8개 셀 사상을 다시 도출한다.
- 조커를 어떤 코드, 테스트, 데이터에도 넣지 않는다. 카드는 정확히 52장이다.
- 점수 수치를 정하거나 코드에 넣지 않는다.
- 이전 구현 코드나 외부 마커 라이브러리를 가져와 재사용하지 않는다.

## 8. 교차 확인용 기준값

설계 검토에서 2²⁵ 패턴 전체를 열거해 얻은 값이다. 마일스톤 1의 `verify-bound` 스크립트가 **독립적으로 다시 계산**해야 하며, 값이 다르면 불일치를 기록하고 멈춘다.

| 항목 | 기준값 |
|---|---|
| 균형 탈락 (검은 셀 수가 9~16 밖) | 3,615,562 |
| 자기 거리 탈락 (D4 비항등 변환 중 거리 < 5가 하나라도 있는 패턴) | 7,152,896 |
| 변환별 자기 거리 탈락 | R90 74,624 · R270 74,624 · R180 647,168 · Fh/Fv/Dm/Da 각 1,835,008 |
| 둘 중 하나라도 탈락 | 9,456,896 |
| 필터 통과 \|F\| | 24,097,536 |
| V(25,4) | 15,276 |
| 코드 크기 하한 ⌈\|F\| / (8·V)⌉ | 198 (52 이상) |
| 관측 배치 × 이미지 변환 | 81 × 8 = 648개 |
| 반사 판별 가능 / 모호 | 520 / 128 (모호는 ♣·♠ 전용 그룹) |
| 통과 가설 수 | ♥·♦ 포함 그룹 2개, ♣·♠ 전용 그룹 4개 |

이 값들은 이 문서 작성 전에 임시 스크립트로 계산한 것이며 저장소 안의 테스트로 재현되기 전까지는 미재현 값이다.

## 9. 이 작업을 막지 않는 미결정 사항

`docs/open-decisions.md`에 정리돼 있다. 아래 결정은 광학 프로토타입에 영향을 주지 않으므로 기다리지 않는다.

- 광학 조각이 인쇄되는 카드 면
- 예측 전까지 카드 신원을 숨기는 방법
- 무작위 시작 카드 4장이 유효한 Composite Code여야 하는지
- ♣·♠ 전용 그룹의 반사 모호성을 UI에서 다루는 방법
- 일반 카드 앞면 인덱스와 마커 위치 충돌

## 10. 완료 정의

다음이 모두 충족되면 이 작업이 끝난 것이다.

1. `tasks.md`의 마일스톤 0~8이 완료로 표시돼 있고, 각 마일스톤의 실제 테스트 출력이 `docs/optical/results/`에 있다.
2. `npm test`가 작업 브랜치에서 통과한다. 통과하지 않는 항목이 있으면 `findings.md`에 원인과 함께 남아 있다.
3. `codebook.v1.json`이 동결되고, 재생성 결과와 바이트 단위로 같으며, SHA-256이 기록돼 있다.
4. 강건성 보고서에 조건별 식별률·거부율·오식별 건수가 있고, 오식별 건수가 0이거나 실패가 사실대로 기록돼 있다.
5. 실물 카메라 결과가 없다는 사실이 보고서에 명시돼 있다.
6. 변경은 작업 브랜치에만 있고 병합·게시되지 않았다.

## 11. 첫 번째 실행 단위

**마일스톤 0 + 1**: 프로젝트 스캐폴딩, 결정적 52장 코드북 생성기, 코드북 동결, 경계 수치 재현 스크립트.

완료 조건은 다음과 같다.
- `npm test`가 실행되고 결과가 `docs/optical/results/m0-*`, `m1-*`에 저장돼 있다.
- 52개 패턴이 고유하고, 같은 시드의 두 번 생성이 바이트 단위로 같다.
- `bound.json`의 수치가 8절 기준값과 일치하거나, 불일치가 기록돼 있다.
