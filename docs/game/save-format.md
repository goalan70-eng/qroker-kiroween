# Save format and privacy (task 20.1)

Code: `src/game/persistence/save-format.ts`. A save is a replay log, not a snapshot. Anyone who can read the text can rebuild the whole game.

## What the serialized envelope contains

| Field | Content | Privacy effect |
| --- | --- | --- |
| `seed` | The Seed. | Reproduces the whole deal: every Hand, the deck order and the initial board. Not secret once the text is readable. |
| `config` | Seat names, kinds, difficulties, score configuration, identity visibility, rules version. | Player names are personal data. |
| `actions`: `PLACE` | Seat, card id, cell, orientation of every accepted placement. | Shows which cards were played, to whoever reads the save. |
| `actions`: `SUBMIT_GUESSES` | Seat and Guess per Quad_Key, for EVERY seat including AI seats. | A save made during `GUESS_COLLECT` holds the Guesses of the batch that is not yet revealed (the engine keeps them sealed in `pending.guesses` and in `log`). The UI must not show them before the reveal. |
| `actions`: `ACK_REVEAL` | Marker only. | None. |
| `savedAtIso` | Caller-supplied UTC time stamp. | Reveals when the game was saved. |
| `format`, `saveVersion`, `rulesVersion` | Versions. | None. |

## What it does not contain

No `GameState`, no deck array, no Hand arrays, no board, no `pending`, no scored groups. Leaving them out does not make the text secret: they are derivable by `replay(seed, config, actions)`. `localStorage` is readable by any script of the same origin and by anyone with DevTools or file access. No encryption is implemented and none is claimed; it would need a separate approved requirement.

## Division of labour

- `parseSave`: structure and version only. Strict: unknown keys, `__proto__`, `constructor` and `prototype` keys are CORRUPT. It never throws and never echoes the input. Text over 1,000,000 characters and more than 1,000 actions are CORRUPT.
- `replay` (core): engine semantics. Illegal placements, wrong cards, Guess values (`3.5`, `99`, empty Guess sets), duplicate submissions and actions after the end pass the parser and are rejected by `replay`. Task 20.2 must map a replay rejection to `DISCARDED`.

## Concerns for task 20.4

1. A resumed multi-human game must go through the gate again. No private view before it.
2. Do not display or log saved Guesses, Hands or the text, and never send them anywhere.
3. Save only after an accepted Action and remove the save at `ENDED` (requirement 18.8).
4. Decide whether to store while a batch is pending (a save then holds unrevealed Guesses). The alternative is to save only at batch boundaries, at the cost of losing the open batch on reload.
5. Owner decision: whether the displayed Seed and the stored Seed need protection (links with IC-13).
6. Encryption: none, see above.

## Unresolved questions

- `core/score` import: design.md lists only `core/replay` and `core/types` for `persistence/`; `RULES_VERSION` lives in `core/score`. No boundary rule forbids it, so the module imports that one constant. Either extend the design table or move the constant.
- `savedAtIso` checks ranges but not the calendar (`2025-02-31T00:00:00Z` passes).
- The parser accepts an empty or non-monotone `rewardByError` table and any finite Guess; the engine rejects them (`validateGameConfig`, `validateGuess`).

## Storage adapters and loading (task 20.2, `persistence/storage.ts`)
- **Durability flag.** `KeyValueStore` has one optional extra member, `durable`. The design interface cannot tell a real browser store from a memory fallback, so a store without the member counts as NOT durable. `memoryStore()` is not durable. `browserStore()` is durable only when the storage exists, has the three functions and survives a probe write; otherwise it returns a memory store (never throws). After creation, operations on a durable store may still throw: `saveGame`, `loadGame`, `clearSave` and the prefs functions catch everything.
- **`saveGame(store, state, nowIso)`** returns `{ ok: true, durable }` or `{ ok: false, reason: 'STORAGE_ERROR' | 'INVALID_STATE' }`. The text is checked with `parseSave` before it is written. A write is not read back (a silent drop without an exception cannot be detected). ENDED state: nothing is written and the save is removed (requirement 18.8); if that removal throws, the result is `STORAGE_ERROR`.
- **`loadGame(store)`** returns `NONE` (`readFailed: true` when `getItem` threw: nothing is removed), `RESUMABLE { state, envelope }`, or `DISCARDED { reason, removed }`. Reasons: `CORRUPT`, `SAVE_VERSION`, `RULES_VERSION`, `REPLAY_REJECTED` (any replay or config rejection), `GAME_ENDED`, `INVALID_VALUE` (stored value is not a string). Every discard removes only `SAVE_KEY`; `removed` is false if that threw. Load never writes (a MIGRATED envelope is not re-saved) and no result holds save text or engine detail.
- **For task 20.4:** show the "this game cannot be saved" notice when `saveGame` returns `ok === false` or `durable === false`.
- **Preferences** (`readPrefs`/`writePrefs`, `PREFS_KEY`): persistence stores `{ prefsVersion: 1, language, setup }` as plain JSON (at most 4096 characters) and imports nothing from `ui/` or `i18n/`. 20.4 validates `language` with `isLang` and `setup` with `sanitizeSetupPrefs`. Prefs hold no seed and survive `clearSave`, discards and ENDED saves.

## Property tests (task 20.3, `persistence/save.properties.test.ts`)
- **Property 27 (round trip).** Reachable states only: `newGame` plus `reduce` with actions from `core/testing/state-generators` (`randomLegalAction`, `legalPlacements`, `advanceUntil`); nothing is cast to `GameState`. A case draws a seed (boundary values 0, 1, 65535, 65536, 2^31 - 1, 2^31, 2^32 - 2, 2^32 - 1 with weight), 1..4 humans, BEGINNER/ADVANCED AI seats (EXPERT is not generated), both visibility modes, varied seat names and score tables, a `savedAtIso`, a play style, choice numbers and a TARGET (empty log, PLACEMENT, GUESS_COLLECT with 0..3 submissions, a batch of two codes with 0..3 submissions, REVEAL, ENDED). Checks: `parseSave(serializeSave(envelope))` is `OK` and `toEqual` the envelope; serializing the parsed envelope gives the same text; `replay` of the parsed log is ok and `stateEquals` and `toEqual` the original state. Three groups of 60 cases (`p27a`/`p27b`/`p27c`, base seeds 20270627, 20270634, 20270635); each group runs as 4 `it`s of 15 cases with seeds base, base + 1000, base + 2000, base + 3000 (`SEED_P27_GROUPS`, `NUM_RUNS_P27` = 15). Each `it` checks 15 cases, at least 8 non-empty logs, at least 2 phases and no EXPERT seat; the 60-case coverage guards (`MIN`) are checked on each group's sum in `afterAll` once all four parts passed.
- **Observed coverage (flagged run, 180 cases):** GUESS_COLLECT 71 (submitted 0/1/2/3: 16/22/19/14), REVEAL 34, ENDED 29, PLACEMENT 46; empty log 12; two-code batches 24 (18 with at least one submission); humans 1/2/3/4: 50/56/33/41; OWNER_ONLY 78, FACE_UP 102; boundary seeds 51 (seed 0: 9, seed 2^32 - 1: 8); longest log 83 actions; 0 EXPERT seats. Per group (60 cases) the smallest counts are PLACEMENT 11, REVEAL 10, ENDED 9, empty log 2, two-code batches 5, submitted 0..3 at least 4, humans at least 9, visibility at least 25, boundary seeds 12; the group thresholds are well under these, so a generator that stops reaching a phase fails. Per 15-case part: non-empty logs 12 to 15, 3 or 4 phases.
- **Property 28 (parser robustness).** Inputs: arbitrary strings (ascii, unicode, binary with lone surrogates and NUL, graphemes), `fc.json`, `fc.jsonValue`, `fc.anything`; every strict prefix of five valid saves (10,802 prefixes, all CORRUPT; one `it` per fixture: ENDED 5417, REVEAL 2301, GC2 1500, PLACEMENT 1044, EMPTY 540) plus random truncations with a tail; structure-aware mutations of the JSON tree of valid saves (delete key, add unknown key, replace node, swap nodes, swap/duplicate/trim actions, malformed actions and Guess submissions, damaged seats and score config, `format`/`saveVersion`/`rulesVersion` set to integers, floats, strings, null, `__proto__`/`constructor`/`prototype` keys, reformatting, BOM/NUL prefix); nesting up to 4,000 levels alone and inside a save; once-built oversized texts at and around `MAX_SAVE_TEXT_LENGTH` (1,000,000, also 500,000 levels of nesting) and `MAX_ACTIONS` (1000 accepted, 1001 CORRUPT), seat names of 200 and 201 units. Postconditions for every input: no throw, one of the four kinds (never `MIGRATED` with the production constants, `INCOMPATIBLE` reasons only `SAVE_VERSION`/`RULES_VERSION`), `Object.prototype` and `Array.prototype` unchanged. For every `OK`: `serializeSave` is deterministic, re-parse is `OK` and equal, `replay` does not throw.
- **Observed outcome distribution (mutations, 2 `it`s x 1000 runs, seeds 20270630 and 20271630):** OK and replay ok 99/96, OK and replay rejected 60/75, CORRUPT 659/645, INCOMPATIBLE/SAVE_VERSION 60/82, INCOMPATIBLE/RULES_VERSION 122/102 (per-`it` thresholds 50, 30, 300, 30, 50). Strings: 1500 of 1500 CORRUPT. Depth: 200 of 200 CORRUPT. Test-only migration registry through `parseSaveWith` (invented v1 shape with `moves`, v2 with `actions`, current 3; 1000 runs): OK 57, MIGRATED from 1: 117, from 2: 86, CORRUPT 607, INCOMPATIBLE 133; every MIGRATED envelope is at the current version, re-parses as `OK` and replays without throwing. `loadGame` over mutated texts (4 `it`s x 200 runs, seeds 20270633, 20271633, 20272633, 20273633): RESUMABLE 21/19/13/17, DISCARDED CORRUPT 129/129/142/131, SAVE_VERSION 15/14/7/11, RULES_VERSION 21/20/20/21, REPLAY_REJECTED 12/16/12/19, GAME_ENDED 2/2/6/1. Each `it` requires RESUMABLE >= 5, CORRUPT >= 60 and at least 2 other discard reasons; the sum (RESUMABLE 70, CORRUPT 531, SAVE_VERSION 47, RULES_VERSION 82, REPLAY_REJECTED 59, GAME_ENDED 11) is checked in `afterAll` against 30, 250, 15, 30, 20, 3; a discard removes only `SAVE_KEY` (a stored prefs value is untouched) and a resume equals the replay of the parsed envelope.
- **Division of labour.** `OK` does not imply that the log replays: the test counts both outcomes and requires both. `loadGame` converts a replay rejection to `DISCARDED`.
- **ENDED policy (not part of Property 27).** A separate deterministic test shows that `saveGame` of an ENDED state removes the save and `loadGame` of an ENDED log is `DISCARDED` `GAME_ENDED`. The format and replay round trip of Property 27 still holds for ENDED states.
- **Reproducibility.** Every `fc.check` uses a fixed seed and run count (constants at the top of the file). A failure message gives the seed, `path`, `numRuns` and the shrunk counterexample cut to about 1000 characters; to replay one, add the reported `path` to the `fc.check` parameters. `QROKER_PROP_REPORT=1` prints aggregate counts and timings only (no texts) after the file.
- **Limits.** Synthetic data only, no browser or real storage. EXPERT seat labels are not generated (the parser accepts them; covered by `save-format.test.ts`). Shrinking of a P27 case re-plays whole games, so it can be slow. Timings: one 800-run `loadGame` `it` took 6.5 to 7.9 s with other apps at 67 to 77 % CPU and hit the 5000 ms default timeout, so the long properties are split (no timeout overrides). Measured with `npx vitest run src/game/persistence src/game/boundaries.test.ts --maxWorkers=2` on 12 logical cores: quiet, the slowest `it` takes 0.5 to 0.75 s (whole run 8 to 10 s); with 12 busy-loop processes (`while` loops, one per core), the slowest are a P27 part 2.0 s, the migration `it` (1000 runs) 1.9 s, a mutations part 1.7 s, the ENDED prefixes `it` 1.7 s, each `loadGame` part 0.2 to 0.6 s (whole run 30 s). Before the split the same contention gave P27 `it`s up to 6.0 s (a timeout), mutations 3.0 s and all prefixes 3.0 s.

## Integration (task 20.4)
- **Save points.** The controller calls `saveGame` right after every ACCEPTED Action (human placement, Guess submission, reveal acknowledgement, each AI Action) and when `begin` creates a game; a rejected Action saves nothing; an abandoned game calls `clearSave`; an ENDED state removes the save through `saveGame` itself. A failed save never rolls back the Action; it sets the write-failed notice.
- **Startup flow.** `main.ts` builds `browserStore()` and the clock; the controller reads `loadGame` once before the first render. `RESUMABLE` shows a Continue/Discard prompt instead of the setup (the sealed state stays in the controller, the model holds only the saved time and the human count); `DISCARDED` shows the localized notice for its reason code and the setup; `NONE` with `readFailed` shows the read-failed notice. Preferences are read from `PREFS_KEY` separately and survive every discard.
- **Privacy.** The save holds the Seed and every accepted Action, including unrevealed Guesses (the browser spec B shows `SUBMIT_GUESSES` in the stored text of a pending batch). `localStorage` is readable by anyone with DevTools; nothing is encrypted. The "saved automatically" status line appears only after a durable save of a running game. Open owner decisions: IC-13 (showing the Seed) and saving during a pending Guess batch.
- Browser evidence: `e2e/persistence.spec.ts` (see [ui-progress.md](ui-progress.md)).
