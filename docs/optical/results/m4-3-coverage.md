## Findings and limits

- Guaranteed vs measured: the G1/G2 assertions (correction up to the radius, radius-1 rejection of 2-3 flips, no cross-card acceptance below d_id - radius, attainment at d_id - radius) hold for every case of the frozen codebook. False-acceptance and wrong-transform counts are measured values, equal to the exact enumeration, not guarantees.
- Image-level cells (`m4-3-counterexamples.md`): n = 300 per (radius, k) cell, synthetic images, never pooled. They are finite samples; the exact enumeration is the authoritative bit-level statistic. Zero false acceptances give only the one-sided 95% upper bound 0.00993608 (about 1.0%), not a zero rate.
- Detector finding (not changed, `detect.ts` is out of scope): in cell radius 1, k = 5, trial 123 (card D-2, transform R180, modulePx 10, offset 17,13, flipped bits 0,14,19,23,24, bits 0x5AC54) `detectMarkers` returns two markers: the real one and a spurious one at corners (67,53),(77,53),(77,73),(67,73) read as 0x1FFFFFF (a 1x2-module black blob inside the data area, accepted as a marker). The spurious fragment decodes as CORRUPTED_FRAGMENT, so it cannot create an identity, but a consumer that expects exactly one fragment per physical marker (task 5 grouping) must handle it. The cell table records this in the column "trials with extra (spurious) fragments".
- Cell radius 2, k = 4 shows 4 false acceptances in 300 (1.33%) against an exact rate of 0.254%; the same seeded draws classified with the bit-level model give the same 4, so the image pipeline agrees with the model draw by draw and the excess is sampling variation of that single cell (probability of >= 4 under the exact rate is about 0.7%).
